# Domain documentation

Before exploring or changing domain behavior, read the [canonical glossary](../../CONTEXT.md) and the relevant decisions in [docs/adr](../adr/).

Root `CONTEXT.md` is the canonical domain glossary. Read and update its definitions when discussing terminology; keep implementation details and operational guidance in `README.md`. Context files scoped to a particular planning phase remain separate planning artifacts.

Use the glossary's names in code discussions, tests, issues and design proposals. Compare behavioral claims with current code; distinguish accepted policy, implemented behavior and proposed changes.

If a proposed change contradicts an ADR, identify the decision and explain the conflict explicitly before changing the policy. Preserve the distinction between API reimbursement totals and the PDF summary's documented mileage exclusion.
