## Corrections/qualifications for `FULL_APP_AUDIT.md`

The audit’s frontend material is useful only after applying the following distinctions. The prior verification’s detailed dispositions are at `FULL_APP_AUDIT_VERIFICATION.md:10-25,27-60,83-110`.

- **False claims to remove:** DESK-01’s alleged `max-w-lg` route wrappers (the form itself has a constrained column inside a responsive layout); UX-02’s “only first receipt” (detail page maps all receipts); UX-05’s first-page limit (no `page` means unpaginated list; draft results are client-filtered); UX-07’s missing insurance subtitle and Recharts white tooltip (`SpendChart` is hand-built SVG); FE-04’s stuck portal overlay cause; FEAT-10’s claim that successful/cancelled OCR sources are never deleted; “invalid BCP-47” for `en-EU` (`FULL_APP_AUDIT_VERIFICATION.md:12-13,17-22`).
- **Supported frontend behavior defects:** full-page search omits users/insurance/advances while the dropdown has them (`app/search/page.tsx:43-46,75-155`); dashboard card is labelled “Approved” while using paid counts/link (`DashboardClient.tsx:714-725,783`); date extraction/formatting risks; unscoped persisted query state/service-worker navigation cache are privacy risks; bulk review request-level errors and some mobile controls need review.
- **Risk, not confirmed outcome:** IDB query persistence uses one global record and restores selected query families before identity scoping; SW stores successful navigation responses by URL and `/offline-shell`; logout clears browser caches, but auth expiry path does not. This justifies privacy-isolation review, **not a demonstrated cross-user leak** (`queryPersister.ts:5-9,110-149`; `Providers.tsx:11-24`; `sw.js:81-96`; `AuthProvider.tsx:142-169`; verification `:48-50`). Some query keys contain user ids; no browser reproduction was run.
- The audit’s observation that logout deletes all Cache Storage entries is still source-true (`AuthProvider.tsx:153-165`; `sw.js:32-37`); whether this breaks offline cold start for a later login needs a browser check. Its proposed PWA update-toast action is also still absent (`PwaRegistration.tsx:17-24`; `ToastProvider` supports actions).
- **Qualify device/accessibility claims:** exact drawer pixel widths, iOS auto-zoom, safe-area clipping, below-fold report actions, contrast ratios, and per-component target dimensions need rendered/device evidence. Sidebar has focus trapping; reviewed dialogs have inconsistent trapping/escape/scroll lock. Toast live-region allegation is false: individual toasts already use alert/status plus `aria-live`; toast dismiss and lightbox toolbar targets are 44px (`ToastProvider.tsx:81-85,115-120`; `ReceiptLightbox.tsx:153-190`; `FULL_APP_AUDIT_VERIFICATION.md:34-47`).
- **Separate proposals from requirements:** `FEAT-01..14` are product proposals, not verified missing requirements. Capture already uses OCR category id/status locally; form accepts `reportId`; login toggle exists; zoom/pan exists; OCR source cleanup exists. Manual idempotency, field-level OCR provenance, receipt rotation, automatic draft suggestion, extra bulk operations, merchant-history category fallback, saved currency preference, receipt splitting, and web push are enhancements or gaps only if product decides they are required (`FULL_APP_AUDIT_VERIFICATION.md:83-101`).
- **Do not repeat measured-impact claims without their evidence:** percentages, “90% field case,” exact 18–20px widths, “80+ strings,” fixed effort estimates, screenshot/device observations, or “every page double-fetches” are not validated by source inspection. The audit’s own verification records its non-browser limits (`FULL_APP_AUDIT_VERIFICATION.md:8,34-45,103-110`).
